# prev-portal — the legacy rocket site, built by hand

The site published at <https://lion.js.org/prev> is the last rocket build of `docs/`. That build is
frozen: the Astro portal owns the site root, [`/prev`](https://lion.js.org/prev) is a snapshot, and
nothing in the pipeline regenerates it. This package exists only as a local way to build that
snapshot again if the need ever arises.

## Why it is not a workspace member

The rocket toolchain is unmaintained (last releases 2021/2022, the cli still pulls `puppeteer@13`,
`@11ty/eleventy@0.11`, `check-html-links` and its own copies of pre-1.0 `@lion/*` packages), and it
was a root `devDependency` next to the Astro portal, so **every `npm install` in this repo — CI
included — pulled that whole tree in**. Security scanners flagged it, and the packages installed
were used by nothing that ships.

Keeping the build here, in a directory that is deliberately *not* covered by the `workspaces` globs,
means:

- no pipeline (`npm install`, `npm ci`, `npm run build`) touches it: the tree is not installed and
  never built in CI;
- the old versions can no longer be dragged into the root lockfile or into a publication;
- the toolchain is still runnable on a developer machine, on demand.

Do not add this directory to `workspaces`, and do not call it from a root script.

## Usage

```bash
cd prev-portal
npm install          # installs the legacy tree inside prev-portal/node_modules
npm run build        # writes <repo root>/_site/prev
npm run start        # dev server for the same pages
```

The build runs the rocket cli from the repository root with
`-c prev-portal/rocket.config.mjs`, driven by [`build.mjs`](./build.mjs): the pages are the
repository's own `docs/` tree, and the url/data files rocket reads and writes (`.eleventyignore`,
`CNAME`, `docs/_merged_*`) are cwd relative. The cli resolves `@rocket/core`, `plugins-manager` and
`@web/rollup-plugin-copy` itself, from `prev-portal/node_modules`.

Only `_site/prev` in the repository root is meant to be picked up: `npm run deploy` at the root
publishes it to the `gh-pages` branch, which serves `/prev` (the deploy runs with `-a`, so the
untouched `/prev` in that branch survives).

## What is pinned, and why the pins look odd

`@rocket/cli` is pinned to **0.10.2**, the last version that can build this site. The bump to
`^0.21.0` (Sept 2026) dropped the Eleventy based flow for the new engine and the build stopped
working in this repo — that is why the frozen `/prev` is the last one published. Everything else is
pinned to (or overridden towards) the versions the published snapshot was built with, verified by
running the build here:

| pin | why |
| --- | --- |
| `@rocket/cli@0.10.2` | last version that builds the site |
| `@mdjs/core` (override) | `@rocket/eleventy-plugin-mdjs-unified` asks for `^0.9`, which renders nothing |
| `remark-rehype@8` | rocket's `.eleventy.cjs` `require`s it while mdjs `import`s it; the ESM-only v10 gives two different plugin objects and `adjustPluginOptions` fails |
| `slash@3` | the mdjs eleventy plugin `require`s `slash`; v4 is ESM-only and `require` returns a namespace instead of the function |
| `sax-wasm@2.2.4` | 2.3.x declares `"type": "module"` and its CJS entry then throws on require |
| `@mdjs/mdjs-preview`, `@mdjs/mdjs-story` | same versions as the published snapshot |
| `sax-wasm`, `@rocket/{search,drawer}` lit overrides | carried over from the root `package.json`; the legacy tree needs lit 2 |

Unlike the old root setup — where `rocket.config.mjs` imported `@rocket/core`, `plugins-manager`
and `@web/rollup-plugin-copy` while none of them were declared — every package the build needs is
declared here. `npm install` in this directory therefore produces the same table as a fresh clone
would, not a hoisting accident.

## Known limits

- `components/*/api-table/index.html` comes from `docs/**/api-table.md`, which
  `npm run custom-elements-manifest` generates at the *root* (a gitignored file). Run that first if
  the rebuilt pages need those; without it those 38 pages are simply missing.
- Open Graph/social images are generated by the build; `npm install` here skips the Chromium
  download (`PUPPETEER_SKIP_DOWNLOAD=true` in [`.npmrc`](./.npmrc)) to keep it small. Remove that
  line if you need the images.
- This package has no tests and no CI: it is a manual escape hatch, the output is not published by
  the pipeline.
